03

Defects fixed

None of these appeared in any existing status document.

01
Seven stale route paths blocked boot
An earlier reorganisation moved route files without updating index.js. The deleted _merged originals were recovered from git and diffed first — the surviving files are strict supersets, each adding /health, so no route was lost in repointing.
02
255 unresolved imports across 212 files
Repaired by resolver. It refuses cross-tree repairs: 63 cases where a backend file's only name match lives in frontend/ are reported, not rewritten — that is an architecture decision, not a typo.
03
Content negotiation rejected every browser
contentNegotiation substring-tested Accept for application/json, so it rejected */* and the standard browser header. Every browser request would have returned 406.
04
Response-time header killed responses
trackResponseTime set a header inside res.on('finish') — after the response is flushed. The ERR_HTTP_HEADERS_SENT throw escaped into the emitter and destroyed the response instead of surfacing as an error.
05
Rate limiting was never active
rateLimit and standardizeErrorResponse are factories that were registered uncalled. Both have .length === 0, so Express treated the factory as middleware, took the returned handler as a return value, and never received next(). Requests reaching either layer hung forever — and no rate limit was ever applied.
06
Nine services cached a null database pool
this.pool = await getPostgreSQL() at construction returns null before the shared pool initialises, and several of those services' initialize() is never called at all. The cached null then failed every query for the process lifetime.
07
A stale duplicate module tree was being loaded
Four requires escaped backend/ into an Aug-30 copy at EBDESIGN/modules/, whose own relative paths then resolved outside the backend tree. Repointed after verifying the backend copies were supersets.
08
Library service could never find the library
path.resolve(__dirname,'../../..') is the repo root from modules/ but backend/src from backend/src/modules/. It searched backend/src/_EBDESIGN_LIBRARY, found nothing, and indexed zero library files. Now resolves by walking up for the marker directory.
09
Frontend pointed at four wrong ports
No .env existed, so defaults applied — and five files named four different ports, none of them the one in use. config/env.js also treated the base URL as an origin while services/api.js treated it as the full base, so setting it produced /api/v1/api/v1.
10
Library indexing was O(n²) and hashed 3 GB per cold start
A membership test rebuilt a 1,500-element array for each of 830 files (129s → 70s once fixed), and every first request hashed the entire library for hashes only two methods read. Hashing is now deferred.
04

Corrections to prior reporting

“Zero migrations executed” — wrong

Every project document, and my own first report, stated the database had never been migrated. In fact 384 migrations were applied on 2026-09-05, creating 1,390 tables. The database was never empty.

“Snapshot folders are byte-identical copies” — wrong

Asserted here and in _UNIFIED_PROJECT/audit/FINAL_INTEGRATION_REPORT.md. Measurement found 23,554 genuinely unique files (683 MB), including ~15,500 source files. Deleting on that advice would have destroyed the unmerged work in _MERGE_LAB and the separate clones under New folder/.

“163 lost API endpoints” — wrong, and nearly acted on

A route diff suggested the live tree had lost 163 endpoints across 48 files. It had not: the snapshots hold a uniform five-route generated CRUD scaffold that the live tree replaced with 12–14 real domain endpoints each. Restoring them would have overwritten working implementations with stubs.

“96% complete” — not reproducible

That figure counted files that exist. Measuring whether files contain behaviour gives: backend services 48% substantive, backend routes 7%, frontend pages 14%, and tests 3% — 1,040 of 1,122 test files are stubs that assert nothing.
