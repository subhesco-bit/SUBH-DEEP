05

Two findings worth acting on

The migration backlog is a schema-ownership problem, not a list of bugs

Eight migrations failed on deleted_at. Adding it moved all eight to user_id. They open with CREATE TABLE IF NOT EXISTS against tables an earlier migration already created with a different shape, so creation is skipped and every subsequent column reference fails in turn. Patching column by column chases a cascade. Someone has to decide which definition is authoritative — the earlier table or the later migration.

The reference data now has one backup, and it is in git

3,327 curated rows — the NE variety directory, HSN/GST mappings, nutrients, government schemes, the chart of accounts — existed only inside one Docker volume. backend/src/database/seeds/001_reference_data.sql reproduces 1,135 of them and restores clean into an empty database. Wage and payroll tables were checked specifically and are empty. Note that _MERGE_LAB, which holds the only copies of ~9,000 unmerged source variants, still has no backup at all.

How these numbers were obtained

Every figure is probed against the running server or queried from the database. Static analysis was wrong six times during this work — reading index.js for route mounts, probing without a token, reading a truncated route listing, missing dynamically-registered effectors, quoting pg_stat_user_tables without ANALYZE, and guessing endpoint URLs.
