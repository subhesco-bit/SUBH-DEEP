# API-004: PUT /api/v1/products/:id/update

**Phase:** 4.1 (Critical Routes)  
**Service:** productService  
**Priority:** P0 - Critical  
**Status:** Specification Complete  

## Endpoint Specification

### Method & Path
```
PUT /api/v1/products/:id/update
```

### Purpose
Update an existing product in the catalog. Used by product owners and administrators to modify product information.

### Service Dependency
- `backend/src/services/legacy/productService.js`
- Method: `updateProduct(productId, updateData)`

## Request Specification

### Headers
```
Authorization: Bearer {access_token}
Content-Type: application/json
```

### URL Parameters
- `id` (uuid, required): Product ID to update

### Body Schema
```json
{
  "name": "string (optional, min 3 chars)",
  "description": "string (optional, min 10 chars)",
  "category_id": "uuid (optional)",
  "state_id": "uuid (optional)",
  "unit_id": "uuid (optional)",
  "base_price": "number (optional, > 0)",
  "gi_status": "string (optional, enum: none, pending, approved, rejected)",
  "organic": "boolean (optional)",
  "images": ["array of image URLs"],
  "varieties": ["array of strings"],
  "seasonal_availability": ["array of strings"],
  "nutritional_info": {
    "calories": "number",
    "protein": "number",
    "carbs": "number",
    "fat": "number"
  },
  "storage_requirements": "string",
  "shelf_life_days": "number",
  "is_active": "boolean"
}
```

### Validation Rules
- User must have product update permission OR be the product creator
- Product must exist in database
- Category, state, and unit must exist if provided
- Base price must be positive if provided
- At least one field must be provided for update

## Authentication Requirements
- Valid access token required
- User must have `product:update` permission OR be product creator
- Rate limiting: 20 requests per minute per user

## Security Considerations

- Prevent modification of created_by field
- Sanitize all user-provided content
- Implement audit logging for product updates
- Rate limit to prevent abuse
