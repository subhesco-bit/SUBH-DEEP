EBDESIGN STABILIZATION RULES

CURRENT OBJECTIVE:
REMOVE EXISTING BUGS, ERRORS, BROKEN LINKAGES,
WRONG BROADCASTING, ROUTING FAILURES AND INTEGRATION DEFECTS.

NOT CURRENT OBJECTIVE:
PROJECT COMPLETION OR NEW FEATURE DEVELOPMENT.

RULES:

1. Never equate scanner observation with confirmed defect.

2. Never repair hundreds of files because one shared diagnostic
   mechanism broadcasts an error.

3. Fix root cause before downstream symptoms.

4. Preserve existing implementation.

5. Never delete, regenerate, overwrite, move or merge components
   merely because a heuristic marks them incomplete.

6. Verify ownership before changing a route, service or component.

7. Repair in bounded batches.

8. Test immediately after each repair batch.

9. If a repair causes regression, stop that repair branch.

10. Maintain evidence of:
    BEFORE
    CHANGE
    AFTER
    TEST RESULT

11. Project completion remains disabled until stabilization closes.

12. Final stabilization gate requires:
    build
    lint
    imports
    routing
    frontend/backend linkage
    backend dependency linkage
    runtime health
    database/infrastructure connectivity
    regression validation.
