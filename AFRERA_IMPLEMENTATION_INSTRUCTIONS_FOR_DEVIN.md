## CRITICAL IMPLEMENTATION RULES

### Rule 1: Digital Organism Architecture
Every software component must possess:
- Structure
- Function
- Intelligence
- Communication
- Memory
- Energy
- Protection
- Adaptation
- Healing
- Evolution

### Rule 2: Self-Similarity
The same structural pattern must repeat at all levels from the smallest instruction to the entire platform.

### Rule 3: Multi-Engine AI
AI does NOT equal an LLM. Use the right tool for every task:
- Rule engines for deterministic logic
- Vision models for image processing
- Forecasting models for predictions
- Optimization models for resource allocation
- LLMs for natural language understanding
- Knowledge graphs for relationship queries

### Rule 4: Vendor Independence
All AI components must be vendor-independent. Use open-source models (Llama, Mistral, DeepSeek, Qwen) and allow easy swapping of engines.

### Rule 5: 30-Level Completeness
A module is complete only when all 30 levels are satisfied, not merely when code compiles or UI is finished.

### Rule 6: Biomimicry with Measurable Benefit
Adopt biomimicry patterns ONLY where measurable benefit exists. Every mapping must produce a measurable architectural benefit (latency number, recovery time, defect class prevented).

### Rule 7: Legal Compliance
Only process legal public-domain data. Respect robots.txt, rate limits, and legal boundaries. Never access private systems or bypass access controls.

### Rule 8: No Code Copying
Use AI for knowledge extraction and reimplementation. Never copy proprietary code or content.
