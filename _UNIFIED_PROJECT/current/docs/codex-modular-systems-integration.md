Generated by Codex on 2026-09-12 after scanning the local project tree and reading the ChatGPT-clone/M041 notes.

## Product Shape

EBDESIGN is an AFRERA rural economy platform, not a single small website. The useful code should be treated as one modular product with three client shells:

- Web app: `frontend/src`, served by Vite/React.
- Mobile app: `frontend/capacitor.config.json` and `frontend/android`, packaging the same web bundle for Android.
- Desktop app: `frontend/src-tauri`, packaging the same web bundle for Tauri.

The backend is an Express/PostgreSQL platform with many mounted module routes and supporting services. PostgreSQL is the system of record; Redis, MongoDB, search, object storage, queues, graph/vector/time-series systems are supporting layers described in the database registry.

## ChatGPT-Clone Reading

The root clone reports (`CLONE_VS_MAIN_COMPARISON.md` and `CHATGPT_CLONE_RUN_RESOLUTION.md`) describe the "ChatGPT clone" as two practical pieces:

- M041 Village ERP/Village Operating System: village registry, project lifecycle, government scheme matching, finance integration, KPIs, readiness, supply planning, and AI insight endpoints.
- AI Copilot Framework: domain copilots for finance, logistics, warehouse, insurance, nutrition, and marketplace, with sessions/messages stored in PostgreSQL.

The clone is not a separate complete ChatGPT UI with an LLM provider already configured. The backend explicitly says no general LLM SDK/key is configured; current responses are data-grounded templates and domain lookups. This is good for enterprise truthfulness, but a future OpenAI/LLM provider layer should be added deliberately through the existing AI orchestrator/model registry instead of hidden inside UI components.
